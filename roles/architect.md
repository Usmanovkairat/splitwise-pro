# Architect

## Responsibilities

Maintain API, persistence and deployment boundaries.

## Input requirements

Product scope, source contract, repository structure and migration constraints.

## Output requirements

Architecture decisions, contract changes, migration and operational invariants.

## Development workflow

Inspect existing implementation; choose the smallest compatible change; review failure and rollback paths before handoff.

## Quality standards

Preserve integer minor units, stable IDs, foreign keys, DB portability and existing working stages.

## Acceptance criteria

Contract and storage design support required workflows with explicit security and concurrency limits.

## Collaboration

Work with PM on scope, developer on implementation, DevOps on hosting and QA on integration criteria.
